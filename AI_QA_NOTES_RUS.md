# AI Quality Engineering — заметки

## AI-pipeline (конвейер AI-системы)
данные (data) → подготовка данных (preprocessing) → обучение (training) → оценка (evaluation) → деплой (deployment) → использование модели (inference) → мониторинг (monitoring)

## Интерпретация через QA
набор данных (dataset) = тестовые данные (test data)  
обучение (training) = процесс сборки системы (build system)  
оценка (evaluation) = проверки через метрики (assertions)  
использование модели (inference) = поведение системы (system behavior)  
мониторинг (monitoring) = QA в production (production QA)

## Основные идеи
QA в AI тестирует поведение модели и качество решения задачи, а не точное совпадение с ожидаемым результатом.

Дефекты данных (data defects):
- недостаток данных (insufficient data)
- неконсистентность данных (inconsistent data)
- ошибки разметки (labeling errors)
- смещение данных (bias)
- дрейф данных (data drift)

Качество модели (model quality) — способность модели стабильно решать задачу на новых данных.

Чтобы измерить качество таких решений, используют матрицу ошибок (confusion matrix).

Она состоит из четырёх чисел:

True Positive (TP) — правильно нашли положительный случай

True Negative (TN) — правильно нашли отрицательный случай

False Positive (FP) — ложная тревога

False Negative (FN) — пропустили важный случай

Это фундамент. Из этих четырёх чисел считаются почти все метрики.

Теперь сами метрики.

Accuracy (точность в общем смысле)

Формула:

accuracy = (TP + TN) / (TP + TN + FP + FN)

Это просто доля правильных решений.

QA-аналог:
“сколько тестов прошло”.

Но accuracy часто обманывает.

Если 99% транзакций нормальные, модель может говорить “всё нормально” и иметь accuracy = 99%, но быть бесполезной.

Поэтому появляются другие метрики.

Recall (полнота)

Формула:

recall = TP / (TP + FN)

Смысл:
“сколько реальных проблем мы нашли”.

QA-интуиция:
не пропускаем критические дефекты.

В fraud-системе recall важнее accuracy.

Precision (точность положительных)

Формула:

precision = TP / (TP + FP)

Смысл:
“сколько найденных проблем действительно проблемы”.

QA-интуиция:
не создаём ложные дефекты.

F1-мера

Это баланс precision и recall:

F1 = 2 × (precision × recall) / (precision + recall)

Она используется, когда важно и не пропускать, и не шуметь.

Generalization gap

Это разница между качеством на обучающих данных и на тестовых.

Например:

training accuracy = 0.98

test accuracy = 0.81

Это сигнал переобучения (overfitting).

Метрики в AI работают как вероятностные assertions.
